# Chapter 2 - A Tale of Two Values

## Key Ideas
There are two important parts of software; behavior and architecture. Sadly,
architecture gets overlooked most of the time. 

Furthermore, the author says he would rather have an application that isn't
working, but is well structured, than a application that is working but cannot
be altered. These are extreme scenarios, but a good point is made. It takes
more work to alter the architecture, then the behavior. 

Another part that is sad about the usual state of software development, is that
urgent, but non-important features get pushed before architecture. The
structure is less urgent, but more important. Business stakeholders do not see
the value in this, but it is not their job. It is the software engineer's job
to communicate the importance to the stakeholders. You need to fight for it. 

Lastly, the matrix of Eisenhower is mentioned, which is very applicable in this
context. 

## Core Message
> Fight for the architecture!
